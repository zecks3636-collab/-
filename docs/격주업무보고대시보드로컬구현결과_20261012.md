# 격주 업무보고 대시보드 로컬 구현 결과

- 작성일: 2026년 10월 12일
- 대상: 월간일정표 대시보드의 신규 업무보고 화면
- 구현 범위: 사용자 PC에서 실행하는 로컬 검토판
- 검증 결론: 구현한 로컬 업무 흐름 및 화면 검증 통과
- 배포 상태: 커밋, push, 운영 배포 미실시

## 1. 구현 결과

기존 대시보드에 업무보고 메뉴를 추가한 로컬 검토판을 구현하였습니다. 팀별 및 담당자별 격주 진행사항을 현황표에서 작성하고, 칸반에서 상태를 확인하며, 팀장 확정 후 회의 화면과 PDF로 보관하는 구조입니다.

운영용 `index.html`, `app.js`, `server.py` 및 기존 화면별 CSS와 JS는 변경하지 않았습니다. 로컬 전용 서버가 응답하는 HTML에 업무보고 메뉴와 화면 파일을 연결합니다. 실제 운영 API, 운영 DB, AWS 서비스에는 연결하지 않습니다.

## 2. 실행 방법과 저장 위치

### 2.1 실행

다음 주소에서 로컬 검토판을 확인할 수 있습니다.

**http://127.0.0.1:8094/**

서버를 종료한 후 다시 실행하려면 프로젝트 루트의 `로컬개편실행_업무보고_20261012.bat`를 실행합니다. 실행 파일은 `reference/meeting_launcher_20261012.ps1`을 통해 로컬 서버 상태를 확인하고, 필요한 경우 숨김 창으로 서버를 시작한 뒤 브라우저를 엽니다. 브라우저 자동 열기가 제한된 환경에서는 접속 주소를 표시합니다. Node.js가 필요합니다.

직접 실행 명령은 다음과 같습니다.

```powershell
node .\로컬개편서버_업무보고_20261012.js 8094
```

서버는 `127.0.0.1`에만 바인딩하므로 다른 PC의 공동 접속 용도로 사용하지 않습니다.

### 2.2 저장 파일

| 용도 | 파일 또는 폴더 |
| --- | --- |
| 업무보고 코드와 자료 | `reference/업무보고로컬_20261012/` |
| 실제 로컬 업무보고 저장 | 위 폴더의 `업무보고상태_20261012.json` |
| 기존 화면의 로컬 저장 복사본 | 위 폴더의 `기존화면로컬데이터_20261012.json` |
| PPT 추출 원문 | 위 폴더의 `초기자료_20261012.json` |
| 기존 코드 백업 | 위 폴더의 `기존대시보드백업_20261012/` |
| 기준 파일 해시 | 위 폴더의 `기준파일해시_20261012.json` |
| 검증 스크립트, 결과, 화면, 시험용 PDF | `output/playwright/업무보고로컬검증_20261012/` |

업무보고 저장은 임시 파일 작성 후 교체하는 방식입니다. 저장에 실패하면 메모리의 기존 상태와 작성창 내용을 유지합니다. 서버를 다시 시작해도 저장한 보고 내용은 유지됩니다.

기능 검증은 별도의 상태 파일과 8096 포트를 사용하였습니다. 시험용 담당자 배정, 제출, 확정 및 다음 회차 생성은 사용자의 실제 로컬 초안에 반영되지 않았습니다. 실제 검토용 저장 파일은 1개 회차, 16개 업무, 담당자 미지정, 확정본 없음 상태를 유지합니다.

## 3. 초기 자료와 사용 절차

### 3.1 PPT 반영

참고 폴더의 5개 PPT를 확인하고, 최신 `건기식관리부문 월간회의(2026.10.12).pptx`에서 경영관리팀 6개, 사업관리팀 10개의 업무를 초안으로 반영하였습니다.

담당자 및 업무 상태는 PPT만으로 확정하지 않았습니다. 팀장이 담당자를 배정하고 상태와 원문을 확인한 후 제출 절차를 진행합니다. 여러 업무에 걸쳐 병합된 진행사항은 중복 입력하지 않았으며, 상세창의 PPT 원문에서 확인할 수 있습니다. 원본 파일명, 슬라이드, 행 위치와 파일 해시를 보관합니다.

초기 회의일은 2026년 10월 12일이며, 보고기간은 9월 29일부터 10월 12일까지의 임시 14일입니다. 실제 보고기간과 제출기한을 확인한 뒤 저장하도록 하였습니다. 다음 회차 기본 기간은 10월 13일부터 10월 26일까지이며 수정할 수 있습니다.

PPT의 Wingdings 기호는 화면 및 PDF에서 일반 기호로 표시하되 추출 원문은 보존합니다. 원본 PPT는 변경하지 않았습니다.

### 3.2 검토 순서

1. 업무보고 화면의 로컬 사용자에서 경영관리팀 또는 사업관리팀 팀장을 선택합니다.
2. 보고기간을 확인하고 각 업무를 눌러 담당자, 상태, PPT 원문 및 연결 목표를 검토합니다.
3. 팀원으로 전환하여 자신의 이번 진행사항과 다음 계획을 작성하고 제출합니다. 작성할 업무가 없는 경우에도 보고 사항 없음으로 제출할 수 있습니다.
4. 팀장은 제출 내용을 확인하고 필요한 업무에 수정 요청을 보낸 뒤 팀 보고를 확정합니다.
5. 두 팀이 확정되면 전체 회의본을 조회합니다. PDF 버튼으로 출력 화면을 열고 브라우저 인쇄 대상에서 PDF로 저장을 선택합니다.
6. 다음 회차를 생성하여 미완료 업무를 이어서 작성합니다. 확정본이 있는 팀의 이월 기준은 최신 확정본입니다.

### 3.3 역할과 공개 범위

초안은 같은 팀에만 표시하고, 확정된 팀 보고서는 다른 팀과 부문장에게 표시합니다. 팀원은 자신의 업무를 수정하고, 팀장은 담당자 배정과 팀 확정을 처리합니다. 제출된 보고를 수정하려면 회수 또는 팀장 수정 요청이 필요합니다. 개정본 작성 중에도 이전 확정 회의본은 유지됩니다.

**로컬 사용자 선택은 역할 검토를 위한 기능입니다. 실제 SSO 로그인이나 조직 권한 인증이 아닙니다.** 사용자 명단과 직책은 검토용 설정이며, 실제 공동 운영 시에는 Entra SSO 및 조직 정보로 대체하여야 합니다.

## 4. 디자인 및 벤치마킹 반영

기존 `DESIGN.md`의 Pretendard, 색상, 글자 크기, 버튼 높이와 모서리 기준을 적용하였습니다. 로컬 업무보고에 필요한 추가 규칙은 해당 문서 7장에 기록하였습니다.

현황표를 기본으로 제공하고, 칸반에서는 상태 배지와 작은 카드로 업무를 구분합니다. 상세 입력은 우측 창에 배치합니다. KPI 차트, 순위 및 간트는 추가하지 않았습니다. 칸반은 넓은 화면에서 4열이며 1024px 미만에서는 선택한 상태의 한 열을 표시합니다. 모바일 메뉴는 4열과 3열의 두 줄입니다.

| 참고 서비스 | 확인한 방식 | 이번 구현에 적용한 판단 |
| --- | --- | --- |
| [Linear Board layout](https://linear.app/docs/board-layout) | 동일 업무의 목록 및 보드 전환, 상태 그룹, 간결한 카드와 상세 보기 | 현황표와 칸반이 같은 업무를 사용하고 카드에는 핵심 정보만 표시 |

위 적용 내용은 각 서비스의 화면 구조를 참고한 설계 판단입니다. 외부 서비스에 내부 PPT나 업무 데이터를 업로드하지 않았습니다.

### 5.2 브라우저 확인 내용

- 현황표 및 칸반의 업무 개수 일치, 검색, 담당자 필터 및 목표 선택
- 두 팀의 16개 PPT 업무 입력, 신규 업무 추가, 담당자 배정 및 원문 검토
- 카드의 실제 드래그 이동 및 상태 선택
- 제출, 회수, 수정 요청, 재제출, 보고 사항 없음, 팀 확정 및 전체 회의본 생성
- 저장 실패 응답 시 입력 유지, 버전 충돌 시 최신 값 비교 후 재저장
- 확정본과 개정 중 초안 분리, 이전 회의본 내용 보존, 다음 14일 회차 및 재조회
- 1440px, 1024px, 768px, 390px, 320px에서 7개 메뉴 이동 총 35개 확인
- 같은 5개 폭에서 칸반 확인, 가로 넘침 없음, 모바일 상단 메뉴 노출
- PDF 출력용 HTML의 전체 확정 업무 및 실제 PDF 한글 표시
- 허용되지 않은 Host 차단, 인코딩된 원본 폴더 경로 및 검증 파일 직접 접근 차단
- 브라우저 JavaScript 실행 오류 없음

기존 6개 화면은 메뉴 이동과 렌더링 회귀를 확인하였습니다. 식단 업로드를 비롯한 기존 화면의 모든 업무 기능이나 실제 운영 저장 계약을 이번 검증에서 다시 실행한 것은 아닙니다. 해당 기존 코드와 저장 파일은 변경하지 않았습니다.

## 8. 격주회의 표시 및 회차 이동 보완

2026년 10월 12일 사용자 추가 요청에 따라 업무보고 상단 회차 표시와 이동 동작을 보완하였습니다.

### 8.1 원인과 조치

기존 화살표는 저장된 회차 배열의 앞뒤 항목만 조회하였습니다. 초기 자료에 회차가 하나뿐이어서 다음 버튼을 눌러도 대상이 없었으며, 별도 안내 없이 동작을 종료하였습니다. 실제 브라우저 클릭으로 동일 증상을 재현한 후 수정하였습니다.

| 항목 | 수정 결과 |
| --- | --- |
| 회차 명칭 | `2026년 10월 격주회의 1차`, `2026년 10월 격주회의 2차` 형식 |
| 월별 번호 | 회의일 순서로 정렬하며 월이 바뀌면 1차부터 새로 시작 |
| 이전 버튼 | 이전 저장 회차로 이동. 이전 회차가 없으면 비활성화 |
| 다음 버튼 | 다음 저장 회차로 이동. 다음 회차가 없으면 팀장에게 회차 추가 창 제공 |
| 신규 회차 | 기본 14일 기간을 확인한 후 명시적으로 저장하면 해당 회차로 이동 |
| 팀원 및 부문장 | 저장된 회차 조회 가능. 신규 회차가 없는 다음 버튼은 비활성화하고 팀장 추가 안내 제공 |
| 조회 실패 | 기존 선택과 화면 내용을 유지하고 재시도 가능 |
| 중복 조작 | 회차 조회 중 이동 버튼과 선택창을 잠금 |
| 회차 추가 창 | 실제 회의일 수정 시 제목의 월별 회차 표시도 갱신 |
| 모바일 | 회차 이동 행을 한 줄 전체에 배치하여 마지막 회차 번호까지 표시 |

회차 번호는 해당 월에 저장된 회의일 순서에 따른 표시입니다. 실제 회의일과 보고기간은 별도로 보관하며, 번호 표시 변경만으로 기존 업무 데이터나 확정본을 수정하지 않습니다. 버튼을 누르는 것만으로 신규 회차를 자동 저장하지 않습니다.

## 9. 팀별 슬라이드 전체보기 및 회의자료 PDF 출력

2026년 10월 12일 사용자 요청에 따라 조회 행에 전체보기 버튼을 추가하고, 회의 중 한 팀씩 넘겨 보는 슬라이드 화면을 구현하였습니다.

### 9.1 사용 방법

1. 업무보고 화면에서 회차를 선택합니다. 과거 회의본을 사용할 경우 회의 보기에서 해당 회의본 버전을 선택합니다.
2. 전체보기 버튼을 누르면 조회 중인 팀부터 슬라이드를 표시합니다. 전체 팀 조회 중에는 경영관리팀부터 시작합니다.
3. 이전 팀 및 다음 팀 버튼, 좌우 방향키로 경영관리팀과 사업관리팀을 한 팀씩 확인합니다.
4. 전체화면 버튼으로 브라우저 화면을 확대하고 창으로 보기 버튼으로 복귀할 수 있습니다.
5. 출력 범위에서 현재 팀 또는 전체 팀을 선택한 후 PDF 출력 버튼을 누릅니다. 열린 출력 화면에서 PDF로 저장을 선택합니다.
6. 닫기 또는 Esc로 조회 화면에 돌아갑니다. 전체화면 상태에서는 먼저 전체화면을 해제합니다.

슬라이드에서 Ctrl+P 또는 Cmd+P를 사용해도 선택한 범위의 회의자료 출력 화면을 엽니다.

### 9.2 표시와 자료 기준

| 구분 | 구현 내용 |
| --- | --- |
| 팀별 슬라이드 | 한 화면에 한 팀만 표시. 하단에 현재 순번 및 이전 팀과 다음 팀 조작부 제공 |
| 긴 내용 | 슬라이드 본문 내부에서 스크롤. 머리글과 하단 조작부는 본문과 별도 영역으로 유지 |
| 조회 필터 | 담당자, 검색, 내 업무 및 빠른 조회 조건과 무관하게 해당 팀의 확정 자료 전체 표시 |
| 닫기 | 원래 조회 필터와 보기 상태를 유지 |
| 확정 자료 | 선택한 회의본 또는 팀 확정본을 표시. 개정 중 초안은 표시하지 않음 |
| 미확정 팀 | 해당 팀의 미확정 안내를 표시. 현재 팀 PDF 출력은 비활성화 |
| 현재 팀 PDF | 현재 슬라이드의 팀만 출력 |
| 전체 팀 PDF | 열어둔 회의자료의 확정 팀 전체를 출력. 팀별 새 페이지로 시작 |
| 버전 유지 | 회의본 ID 또는 팀별 확정 버전을 지정하여 슬라이드와 PDF의 자료 기준을 일치시킴 |
| 과거 회의본 | 과거 버전을 선택하면 전체보기와 PDF에도 같은 버전 사용 |

아직 확정되지 않은 다른 팀의 초안을 전체보기 또는 PDF를 통해 공개하지 않습니다. 실제 회의일과 보고기간, 확정 버전은 PDF에 함께 표시합니다. 긴 자료는 글자를 줄이거나 내용을 생략하지 않고 다음 페이지로 이어집니다.
