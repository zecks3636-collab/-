## 1. 종합 판정

사전검토에서 배포 보류 사유로 제시된 2건과 코드리뷰에서 지적된 식단 삭제 실패 처리(R1), 계약 설명 오류(R2)를 보완하고 실제 `server.py` 저장 계약 기준으로 재검증하였습니다. 배포 전 해결 사항은 모두 조치되었으며, 커밋 파일 구성을 지키면 운영 전환이 가능한 상태입니다. 이 문서 작성 시점에는 push 및 배포를 수행하지 않았습니다.

## 3. 운영 저장 계약 재검증

`server.py`의 식단 처리 방식(이미지 행과 정식 행 혼합 목록, 이미지 삭제 시 행은 남기고 `image_data`만 비움)을 재현한 응답으로 실제 브라우저에서 시험하였습니다. 같은 시험을 보완 전 코드에도 적용하여 문제 재현 여부를 대조하였습니다.

| 시나리오 | 보완 전 | 보완 후 |
| --- | --- | --- |
| 기존 방식 업로드 이력과 오래된 UUID 이미지 행이 함께 있는 주 조회 | 통과 | 통과 |
| 같은 주 2회 재업로드 직후 표시 | 통과 | 통과 |
| 재업로드 후 새로고침 (목록 정순) | 실패: 기존 이미지 표시 | 통과 |
| 재업로드 후 새로고침 (목록 역순) | 통과 | 통과 |
| 메타데이터 저장 실패 후 새로고침 | 실패: 확정되지 않은 이미지 표시 | 통과 |
| 보관 목록 중복 및 이미지 경로 행 노출 | 통과 | 통과 |
| 삭제 후 새로고침 | 실패: 삭제한 식단 재표시 | 통과 |
| 이미지 없는 과거 주의 원본 보기 | 실패: 404 링크 노출 | 통과 |

삭제 후 재표시는 사전검토에 없던 항목입니다. 이미지 삭제 API가 행을 지우지 않아 기존 `주차.jpg` 행이 남는 구조 때문이며, 기존 운영 코드에도 있던 문제입니다. 정식 행만 조회하도록 바꾸면서 함께 해소되었습니다.

초판에서는 이미지 삭제 API가 없다고(405) 기술하였으나 `server.py:392`에 해당 API가 있어 코드리뷰(R2)에 따라 정정하였습니다.

## 3-1. 식단 삭제 실패 처리 보완 (코드리뷰 R1)

기존 삭제는 이미지를 먼저 비우고 정식 행을 삭제하며, 두 응답의 오류를 확인하지 않고 화면에서 식단을 제거하였습니다. 정식 행 삭제가 실패하면 이미지만 사라진 반쪽 상태가 남았습니다.

- `app.js`: 정식 행을 먼저 삭제하고 오류를 확인합니다. 실패하면 안내 후 이미지와 화면을 그대로 유지합니다. 성공한 뒤에만 이미지를 비우며, 이미지 삭제 실패는 정식 행이 없어 화면에 영향이 없으므로 기록만 남깁니다.
- `db.js`: 이미지 삭제 응답의 HTTP 오류와 연결 실패를 오류로 반환하도록 수정하였습니다.
- 서버 트랜잭션 방식은 백엔드와 감사 이벤트 계약 변경이 필요하여 이번 범위에서 제외하였습니다.

| 삭제 시나리오 (정식 행 / 이미지) | 보완 전 | 보완 후 |
| --- | --- | --- |
| 실패 500 / 미실행 | 실패: 안내 없음, 이미지 소실 | 통과: 안내, 화면과 이미지 유지, 새로고침 후 유지 |
| 성공 / 실패 500 | 확인 불가(앞 단계 실패) | 통과: 화면 제거, 새로고침 후 미표시 |
| 성공 / 성공 200 | 통과 | 통과: 정식 행 제거, 이미지 비움 |
| 성공 / 405 (구버전 인스턴스 가정) | 통과 | 통과 |

## 6. 남은 유의 사항

- 재업로드 때마다 이전 이미지 행이 운영 DB에 남습니다. 표시에는 영향이 없으나, 누적량 정리는 운영 자료 확인 후 별도 승인으로 진행합니다.
- 운영 로그인, 운영 API, RDS 실제 자료는 확인하지 않았습니다. 배포 후 로그인한 브라우저로 6개 화면과 식단 업로드 및 재조회를 확인해야 합니다.
- 엑셀 및 PDF 파서는 기존과 같이 외부 CDN을 사용합니다.
- 자동 반영 식단(`menu_auto_poll`)은 해당 주 정식 행에 이미지가 없으면 시트의 미완료 행을 다시 내려받습니다(`server.py:660`). 서버가 시트에 완료 표시를 하지 않으므로, 자동 반영된 주를 삭제하면 다음 접속 때 다시 나타납니다. 수동 업로드 주도 정식 행에 이미지가 없어 자동 반영이 덮어쓸 수 있습니다. 개편 전부터 있던 서버 동작이며, 3장의 "삭제 후 재표시 해소"는 수동 업로드 주에 한합니다. 해결에는 서버 변경이 필요합니다.
